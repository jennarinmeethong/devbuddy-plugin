# ร่างข้อกำหนดการใช้งาน DevBuddy npm client ภายใน G-Able

สถานะ: **เจ้าของเห็นชอบเนื้อหาร่างเมื่อ 2026-10-28; รอปิด checklist ก่อนจัดทำฉบับใช้แจก — ยังไม่อนุมัติ rollout**  
จัดทำ: 2026-10-28  
ผู้อนุมัติ pilot ที่เจ้าของระบุ: `jennarin.meethong`

เอกสารนี้เสนอขอบเขตสำหรับ internal pilot ตามการตัดสินใจที่บันทึกไว้ ต้องให้เจ้าของสิทธิ์
และผู้เกี่ยวข้องตรวจความถูกต้องและอนุมัติก่อนแจกใช้งานจริง การจัดทำหรือเก็บร่างนี้ไม่ได้
อนุมัติ rollout ไม่ยืนยันอำนาจอนุมัติแทนองค์กร และไม่ได้เลือก license ให้ repository ทั้งหมด

## 1. แพ็กเกจที่อยู่ในขอบเขต

- ชื่อแพ็กเกจ: `devbuddy-plugin-client`
- คำสั่ง: `devbuddy-npx`
- รุ่นทดลอง: `1.14.0-next.0`
- ไฟล์: `devbuddy-plugin-client-1.14.0-next.0.tgz`
- SHA-256: `99f0c5ea9e923e924c0df27d40583368493f0fbf2533e8af22f26f73f9d1d10f`

ร่างนี้ครอบคลุมเฉพาะแพ็กเกจ client ข้างต้น ไม่ได้ขยายสิทธิ์ใน DevBuddy server,
repository ทั้งหมด, .NET client หรือซอฟต์แวร์ของบุคคลอื่น

## 2. ผู้ใช้และวัตถุประสงค์ที่เสนอ

เสนอให้บุคลากรภายใน G-Able ติดตั้งและใช้งานเพื่อทดลองและประเมิน DevBuddy client
สำหรับงานภายใน ภายใต้สิทธิ์ของบัญชีและ workspace ที่ server อนุญาตอยู่แล้ว
สิทธิ์ใช้ client ไม่ได้ให้สิทธิ์เข้าถึงข้อมูลของผู้อื่นหรือเปิด AI access ให้โครงการโดยอัตโนมัติ

ผู้อนุมัติต้องยืนยันความหมายของ “บุคลากรภายใน G-Able” หากต้องรวมบริษัทในเครือ
ผู้รับจ้าง คู่ค้า หรือลูกค้า ก่อนเพิ่มบุคคลเหล่านั้นเข้าในขอบเขตผู้รับ

## 3. การรับไฟล์และติดตั้ง

รับไฟล์และ checksum จากช่องทางภายในที่ผู้อนุมัติกำหนด ตรวจ checksum ก่อนติดตั้ง
เก็บชื่อ version ที่ใช้งานเพื่อแจ้งปัญหาและย้อนกลับได้ ไม่ใช้ไฟล์ที่ตรวจแล้ว checksum ไม่ตรง

การติดตั้งใช้ Node/npm และดาวน์โหลด dependencies ผ่าน registry/เครือข่ายที่องค์กรอนุญาต
ชุดนี้ไม่ใช่ตัวติดตั้ง offline ห้ามปิด TLS validation หรือหลบข้อควบคุมขององค์กรเพื่อให้ติดตั้งได้
การตั้งค่า proxy/CA ให้เป็นไปตามแนวทางที่องค์กรรับรอง

## 4. การแจกต่อและการเปลี่ยนแปลง

เสนอให้แจกสำเนาแพ็กเกจ pilot ต่อได้เฉพาะผู้รับภายในขอบเขตที่อนุมัติ ผ่านช่องทางที่กำหนด
พร้อม version, checksum, คู่มือ และเอกสารกำกับที่อนุมัติแล้ว
การเผยแพร่แพ็กเกจนี้สู่ npm สาธารณะ, public repository, public download link หรือผู้รับภายนอก
ต้องมีการอนุมัติแยกต่างหาก ไม่รวมอยู่ในการเลือก internal pilot ครั้งนี้

หากแก้โค้ดหรือ metadata แล้วสร้างแพ็กเกจใหม่ ให้ระบุเป็น artifact ใหม่และตรวจรับก่อนแจก
ห้ามใช้ checksum หรือผลตรวจรับของไฟล์เดิมแทนไฟล์ที่เปลี่ยนไป

## 5. เจ้าของสิทธิ์และ dependencies

ข้อมูลที่เจ้าของแจ้งสำหรับชื่อเจ้าของลิขสิทธิ์คือ `jennarin.meethong`; ต้องตรวจยืนยัน
ความถูกต้องและอำนาจอนุญาตก่อนใช้เอกสารฉบับอนุมัติ การระบุ G-Able เป็นผู้ใช้ไม่ใช่การโอนสิทธิ์
ร่างนี้ไม่ได้แก้หรือเพิกถอนสิทธิ์ที่ให้แก่บุคคลอื่นไว้แล้วในเอกสารหรือการเผยแพร่ก่อนหน้า

Dependencies และองค์ประกอบของบุคคลอื่นอยู่ภายใต้ข้อกำหนดของเจ้าของแต่ละราย
ต้องตรวจรายการ dependency, license และ notices ที่ต้องแนบก่อนแจกแพ็กเกจ
ร่างนี้ไม่เปลี่ยนหรือจำกัดสิทธิ์ที่ license ขององค์ประกอบเหล่านั้นให้ไว้

## 6. ข้อมูลและ credential

ใช้ token ที่ออกให้ผู้ใช้และ workspace ของตนตามสิทธิ์ server ไม่ใส่ token, รหัสผ่าน
หรือข้อมูลโครงการที่ไม่ได้รับอนุญาตในแพ็กเกจ คู่มือ แชตสาธารณะ หรือรายงานปัญหา
ส่งเฉพาะ version, ระบบปฏิบัติการ, ชื่อ host และ error ที่ตรวจแล้วว่าไม่มีข้อมูลลับ

## 7. สถานะ pilot และการแจ้งปัญหา

รุ่นนี้เป็น pilot; เอกสารนี้ไม่ได้เสนอ SLA ระยะเวลาตอบกลับ หรือการรับรองความพร้อม production
การนำไปใช้กับงานหรือข้อมูลที่มีข้อกำหนดเฉพาะต้องผ่านการตรวจของผู้รับผิดชอบตามกระบวนการองค์กร

**ผู้รับแจ้งปัญหาช่วง pilot: `jennarin.meethong` ตามที่เจ้าของเลือก**  
**ช่องทางติดต่อภายใน: Microsoft Teams ชื่อ `jannarin meethong` ตามที่เจ้าของระบุ**

ชื่อ Teams นี้เป็นชื่อที่ให้ไว้สำหรับค้นหาผู้รับเรื่อง ยังไม่ได้ตรวจยืนยันบัญชีหรือลิงก์ติดต่อ
หากค้นหาไม่พบ ให้ผู้จัดแจกยืนยันช่องทางกับผู้รับผิดชอบก่อนเริ่ม rollout

เมื่อพบปัญหา ให้หยุดการใช้งานส่วนที่มีปัญหาและแจ้งผู้รับผิดชอบ สามารถกลับไปใช้ host
configuration เดิมของ .NET client ตามคู่มือได้ ไม่ลบ registry หรือ token ที่ client อื่นใช้ร่วมกัน
เว้นแต่ผู้รับผิดชอบสั่งให้ดำเนินการนั้นโดยเฉพาะ

## 8. รายการที่ต้องปิดก่อนใช้เอกสารนี้

- ยืนยันเจ้าของสิทธิ์และผู้มีอำนาจอนุมัติตามกระบวนการที่เกี่ยวข้อง
- ตรวจและแก้ขอบเขตผู้ใช้ การใช้งาน และการแจกต่อที่เสนอในร่าง
- ตรวจ license/notices ของ dependencies และเอกสารอื่นที่ใช้ร่วมกัน
- ระบุผู้รับแจ้งปัญหาและช่องทางที่ผู้ใช้เข้าถึงได้
- ปิด readiness checklist และอนุมัติ rollout พร้อมวันที่เริ่ม
- บันทึกฉบับที่อนุมัติและแนบกับชุดแจก โดยไม่เรียกร่างนี้ว่าได้รับอนุมัติแล้ว
