# แบบกรอกข้อมูลเตรียมเผยแพร่ DevBuddy npm client

กรอกเฉพาะข้อมูลที่ทราบ ช่องที่ยังไม่แน่ใจเขียนว่า **ยังไม่ตัดสินใจ** ได้
งานพัฒนาและทดสอบดำเนินต่อได้ระหว่างรอข้อมูลนี้ ไม่ต้องสร้าง token หรือส่งรหัสผ่านให้ผู้ช่วย

```text
1. ผู้มีอำนาจอนุญาตเผยแพร่โค้ด
   ชื่อบุคคล/องค์กรเจ้าของโค้ด:
   โค้ดนี้เผยแพร่ต่อสาธารณะได้หรือไม่: ได้ / ต้องตรวจสอบก่อน / ไม่ได้

2. License ของแพ็กเกจ
   License ที่องค์กรอนุมัติแล้ว (ถ้ามี):
   ถ้ายังไม่มี: ขอคำอธิบายตัวเลือกก่อน / ให้องค์กรพิจารณาก่อน
   ชื่อเจ้าของลิขสิทธิ์ที่จะใส่ใน LICENSE:

3. บัญชี npm ที่จะใช้
   มีบัญชี npm แล้วหรือยัง: มี / ยังไม่มี
   Username หรือชื่อ organization (ข้อมูลสาธารณะเท่านั้น):
   คนที่จะดำเนินการ publish ครั้งแรก:
   ชื่อแพ็กเกจที่ต้องการ: devbuddy-client / ชื่ออื่น:
   ชื่อสำรองที่ควบคุมได้ เช่น @ชื่อองค์กร/devbuddy-client:
   ยืนยันสิทธิ์ใช้ชื่อแล้วหรือยัง: ยืนยันแล้ว / ยังไม่ได้ตรวจ

4. การตั้งค่าก่อน release (ตอบเมื่อพร้อม)
   ผู้ที่จะตั้ง trusted publisher ใน npm:
   GitHub repository ที่ต้องการใช้เผยแพร่:
   มีข้อกำหนดขององค์กรสำหรับ release/environment หรือไม่:

5. การอนุมัติ pilot (กรอกหลังเห็นผลทดสอบและ release checklist)
   Version ที่อนุมัติ:
   อนุมัติ prerelease ภายใต้ dist-tag next: ยังไม่อนุมัติ / อนุมัติ
   ผู้อนุมัติและวันที่:
```

## สิ่งที่คุณต้องเตรียมเองเมื่อใกล้ publish

- ยืนยันว่าคุณหรือองค์กรมีสิทธิ์เผยแพร่โค้ด และเลือก license ที่อนุมัติแล้ว
- มีบัญชี npm ที่เข้าถึงได้ และมีสิทธิ์เผยแพร่ชื่อแพ็กเกจที่เลือก
- เตรียมการยืนยันตัวตน/2FA ตามที่บัญชี npm ต้องใช้ โดยทำผ่าน npm ด้วยตัวเอง
- ให้ผู้ดูแลตั้ง trusted publisher ตาม release workflow ที่ตรวจสอบแล้ว
- ตรวจและอนุมัติ version, release notes, หลักฐานทดสอบ และ pilot ก่อนเผยแพร่จริง

ไม่ต้องส่ง **password, OTP, recovery code, npm token หรือ DevBuddy machine token** ในแบบกรอก
นี้หรือในแชต การยืนยันตัวตนและขั้นตอนที่ต้องใช้ความลับให้ทำผ่านหน้าบัญชีของคุณเอง

## สิ่งที่ผมทำต่อได้โดยไม่รอแบบกรอก

- ทำ feature และ regression tests ตาม [แผน](../plan-npx-client.md)
- ตรวจ registry/token compatibility, helper, bridge, error handling และ source guards
- เตรียมแพ็กเกจทดสอบภายใน, SBOM, คู่มือติดตั้งและ rollback
- เก็บสถานะและหลักฐานใน [contract checklist](../npx-client-contract.md)

ข้อมูลในแบบกรอกยังไม่ถือเป็นการสั่ง publish หรือเปลี่ยน plugin defaults ขั้นตอนนั้นรอผล
ทดสอบและการอนุมัติ release ตามแผนอีกครั้ง
