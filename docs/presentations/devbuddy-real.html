03 / Real work

ตัวอย่าง: รับช่วงแก้ปัญหา
ในงานที่มีคนทำไว้แล้ว

ลำดับการใช้ plugin

  1. ค้น decision และ work item ที่เกี่ยวข้อง
  2. อ่านสาเหตุเดิมและข้อจำกัดจาก record
  3. วิเคราะห์ว่าการแก้ครั้งนี้กระทบส่วนใด
  4. สร้าง draft บันทึกผลและ handover

สิ่งที่ทีมได้

ผู้รับงานเห็น เหตุผลเดิม + หลักฐาน + ผลกระทบ + งานค้าง ในบริบทเดียว ก่อนเริ่มแก้

นี่เป็น workflow ตัวอย่างสำหรับ pilot ไม่ใช่กรณี production ที่วัดผลแล้ว

ความสามารถที่รองรับ: search_knowledge, get_record, analyze_change_impact, create_draft, generate_handover04 / 08

05 / Time estimate

ประเมินเวลาอย่างไร
ให้ตรวจสอบย้อนกลับได้

วัดงานชนิดเดียวกัน

  • เลือก task ที่นิยาม “เสร็จ” เหมือนกัน
  • บันทึกเวลา 3 ช่วง: หาบริบท วิเคราะห์ผลกระทบ และส่งต่องาน
  • รวมเวลาแก้คำตอบของ AI และเวลา review ด้วย
  • เทียบกลุ่ม baseline กับกลุ่มที่ใช้ DevBuddy

สูตรที่ใช้รายงาน

เวลาที่ลดได้ (%) =
(baseline − pilot) ÷ baseline × 100

ใช้ค่ามัธยฐานนาทีต่อ task เพื่อลดผลของงานที่ยาวผิดปกติ

ตัวอย่างสมมติ: 120 → 80 นาทีต่อ task = ลด 33%
ตัวเลขนี้เป็นตัวอย่างวิธีคิด ยังไม่ใช่ผลวัดของ DevBuddy

กรอบการวัดเสนอขึ้นสำหรับการทดลอง; เป้าหมาย ≥30% มาจากภาพ REAL ที่แนบมา06 / 08
